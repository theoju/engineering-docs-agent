Cross-Repo Citations

CCE-181 — a docs page must point at a file that lives in a different repository. Writing the path plainly breaks the build. This demo lets you drive the proposed fix and watch what the real linter makes of the result.

What is real here, and what is invented. A prototype that quietly models the code instead of running it can confirm a design that is about to fail — that happened on CCE-175, and the lesson is now recorded in CLAUDE.md. So this file keeps the two halves apart:

  • Ported verbatim from scripts/lint/citation_exists.py at 77c6894: the inline-code scan, the test-id and repo-path patterns, the placeholder rules, fence stripping, and extract_citations. This is the oracle — the judge, never the thing being judged.
  • Invented here, and the actual subject of the demo: renderSiblings and validateConfig. No production code exists for these yet.
  • Not modelled at all: the orchestrator, the page-author agent, file I/O.

If the ported half ever drifts from production, everything below is worthless. That is the one thing to re-check before trusting a verdict here.

The idea being tested

The host declares its sibling repositories. When the author writes a path beginning with a declared name, the pipeline rewrites it before the linter ever sees it — into a clickable link for a public sibling, or into a bare filename for a private one. Anything not declared is left exactly as it is, and keeps failing the way it does today.
