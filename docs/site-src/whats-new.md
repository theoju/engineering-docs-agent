# What's New

## 2026-05-29T14:50:33.678821+00:00
- PR #65: The `docs-agent-nightly` GitHub Actions workflow was updated to mint a GitHub App installation token from the `docs-agent-bot` App (using `actions/create-github-app-token@v1` with secrets `DOCS_AGENT_APP_ID` and `DOCS_AGENT_APP_PRIVATE_KEY`) and use it in place of the default `GITHUB_TOKEN` for both `git push` and `gh pr create`. The `actions/checkout@v5` step also gains a `token:` input pointing at the same App token so the runner's credential helper authenticates correctly. Net change is +24/-1 lines, confined entirely to the workflow YAML.
- PR #63: Two documentation corrections were made: (1) README.md install steps had the wrong secret name — `ANTHROPIC_API_KEY` replaced with `CLAUDE_CODE_OAUTH_TOKEN`, matching the OAuth slot that the nightly workflow and release workflow actually consume. (2) `docs/setup-guide.md` referenced a non-existent workflow filename `docs-agent-run.yml`; corrected to `docs-agent-nightly.yml`, which is the actual file under `.github/workflows/`.
- PR #62: The orchestrator runner now surfaces `partial_reasons` in the GitHub Actions workflow summary. A new `_write_step_summary(state, repo_root)` function reads accumulated partial reasons and appends a bulleted digest to `$GITHUB_STEP_SUMMARY` when that env var is present. It is wired via a `try/finally` block inside `run()` so the digest flushes even when the pipeline hard-fails (invalid config, corrupted state, or an `open_or_append_pr` crash). A shared `_format_partial_digest(partial_reasons)` helper is extracted from the PR body composer and reused by both surfaces, upgrading the existing semicolon-joined warning string to a readable bulleted list in both the GHA step summary and the PR body.
- PR #61: Splits the `markdown_hygiene` lint rule into two distinct rules: `markdown_hygiene_lang` (severity `warn`) fires on missing language tags on opening code fences, while `markdown_hygiene_structure` (severity `block`) fires on unpaired fences and heading-level jumps that genuinely break MkDocs rendering. The old `markdown_hygiene` name is retired; both new names are registered in `TIER1_DEFAULT`. Three new tests cover each rule and runner registration; existing tests are renamed in lockstep.
- PR #60: Corrected the authentication secret name in `docs/setup-guide.md` from the legacy `ANTHROPIC_API_KEY` to `CLAUDE_CODE_OAUTH_TOKEN`. The fix updates line 27 to prescribe the correct OAuth token (introduced in CCE-35) that the Claude CLI reads when dispatching subagents, and adds an inline note distinguishing OAuth tokens from console API keys so readers do not need to look elsewhere.
- PR #50: The bootstrap pipeline now rejects pages with bad YAML frontmatter, absent frontmatter, or thin descriptions, rolling back the written file on failure so the next run retries via the existing idempotency guard. Three new components land: `parse_frontmatter_strict` in `archive_indexes.py` (raises `yaml.YAMLError` vs `ValueError` to distinguish parse failure from missing frontmatter); `description_quality`, the 8th Tier-1 default lint rule, with configurable `min_words`, `forbid_equal_to_title`, and `forbid_trailing_colon`; and `dispatch_verified` in `orchestrator_runner.py`, an additive wrapper around `dispatch_validated` that invokes a post-write callback and deletes the target on failure. A `_BootstrapProgress` helper atomically writes `.engineering-docs-agent/bootstrap.progress.json` on every page transition so external observers can detect in-flight vs crashed state. `run_bootstrap_core` is wired to compose strict-parse + description-quality checks into `dispatch_verified`. 34 new tests bring the suite from 559 to 593.
### Gaps flagged
- theoju/engineering-docs-agent#65: Falls through allowlist (empty) and size_filter (no thresholds configured) to LLM judgment. The change swaps authentication credentials in a CI workflow — replacing the default GITHUB_TOKEN with a GitHub App installation token backed by repo secrets (DOCS_AGENT_APP_ID, DOCS_AGENT_APP_PRIVATE_KEY). Authentication and secrets-handling changes are security-relevant by nature; a senior engineer would expect at minimum a short written plan covering threat model, token scope, expiry handling, and rollback steps before merging. The PR body is thorough but constitutes the author's own narrative, not a reviewed spec.
- theoju/engineering-docs-agent#50: This PR introduces multiple new subsystems (dispatch_verified, _BootstrapProgress), a new public lint rule (description_quality) registered as the 8th Tier-1 default, and a new API (parse_frontmatter_strict). It changes user-visible behavior (new lint rule active by default for all host repos) and adds a new progress-file contract. A senior engineer would expect a written spec and plan for a change of this scope. The PR itself confirms this expectation by including both docs/superpowers/specs/2026-05-28-bootstrap-fail-fast-design.md and docs/superpowers/plans/2026-05-28-bootstrap-fail-fast.md.

## 2026-05-29T04:34:35.184775+00:00
- PR #58: Adds a `_remote_already_processed_window(repo_root, branch, our_head_sha) -> bool` helper to `scripts/orchestrator_runner.py` that detects same-hour duplicate runs before any subagent is dispatched. The helper fetches `origin/<docs-agent-branch>` and reads its committed `state.json` via `git show`; it returns `True` only when the remote branch's `last_successful_run.head_sha` strictly equals the current run's HEAD SHA. A new call site in `_main()` exits 0 with a skip log line when the helper returns `True`, eliminating the working-tree collision (on `whats-new.md` and `state.json`) that caused the post-CCE-42 smoke-test 2/2 to exit 1. Every failure path — network error, absent branch, missing or corrupted `state.json`, schema drift — returns `False` so the runner proceeds normally. Five unit tests cover all documented failure modes. `skills/engineering-docs-agent/SKILL.md` is updated with a new state-transitions bullet and a renumbered procedure step.

## 2026-05-28T23:15:56.279744+00:00
- PR #55: Enables the orchestrator's existing subagent forensic capture mode (DOCS_AGENT_DEBUG_DIR, built in CCE-9 + CCE-12) in the nightly CI workflow and adds an actions/upload-artifact@v4 step with 14-day retention and if: always() so per-subagent forensic files — prompt.txt, stdout.txt, stderr.txt, stream.jsonl, meta.json — survive runner teardown even on failure. No Python source changes; the only modified source file is the nightly workflow YAML. Two new internal spec and plan documents were also added under docs/superpowers/.

## 2026-05-27

### Publish the docs site to GitHub Pages

The docs site can now be published to GitHub Pages through a generic, Node-24-safe GitHub Actions deploy. The setup skill scaffolds a workflow that builds the site, writes `.nojekyll` so the artifact is served verbatim, and publishes it with `upload-pages-artifact` and `deploy-pages` — replacing the legacy Jekyll build that crashed on `{{` and `{%` sequences in source markdown. Non-MkDocs hosts can point it at a custom `build_command` and `site_dir`. See the Operations guide "Publishing to GitHub Pages" for the full flow.
