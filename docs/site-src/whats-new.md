# What's New

## 2026-09-03T12:02:34.829515+00:00
- PR #221: Ran a controlled A/B extraction experiment through graphify's shared library path (same parser, chunker, and out-of-scope filter), varying only the extraction system prompt. The result confirms that the prompt itself was the doc-layer ceiling: swapping the stock prompt for the CCE-125-tuned one raised nodes produced per document from roughly 1 to 6-8, while a separate check found that `_FILE_CHAR_CAP` slices file content mid-token rather than truncating cleanly at a boundary. Findings were written into the existing `docs/runbooks/graphify-extraction-findings.md` runbook and surfaced in the site's what's-new page.
- PR #222: Updated docs/runbooks/graphify-extraction-findings.md to record that the graphify semantic-extraction pipeline now uses a Haiku backend instead of Gemini, and corrected three claims in the runbook that had gone false since the backend switch (including the 'untested at scale' claim, now discharged by a real /graphify . --update run over 81 changed documents).
- PR #223: PR #223 archived the CCE-144 blind-run-detection design as an abandoned effort (closing ticket CCE-150), moving its plan and spec into the archived state. Nine minutes later PR #224 merged that same implementation to main, reversing the abandon decision. PR #223's content (the plan/spec files changed) therefore describes a decision that no longer holds; the PR itself is now only a historical record of a reversed call, not a description of current system behavior.
- PR #224: Splits the previously overloaded `partial` state-tracking flag into two distinct signals: `blind` (a blocking agent was prevented from judging its input at all — e.g. source-collector, pr-summarizer, or notifier dispatch failed to produce usable output) and `degraded` (the pipeline judged its input and deliberately withheld or rejected specific content, e.g. a lint block or time-budget truncation). A run classified as blind now exits with a non-zero status code, cannot advance the watermark cursor, and is excluded from the CCE-101 auto-merge gate. Classification happens by call site rather than by matching on reason strings, and every blocking dispatch reason must now be classified — an unclassified failure defaults to blind so it fails loud instead of silently passing as green.
- PR #228: Adds two net-new documentation files to the repo: CONTEXT.md, a project-wide glossary defining the orchestrator's domain vocabulary (window, baseline, cursor, window head, promotion, ephemeral advance, admission gate, deferral, owed page, forgiveness, held back, partial run, truncation, batch, block, drift), and docs/adr/0001-baseline-advances-on-disk-for-partial-runs.md, an ADR recording the decision behind how the baseline advance is persisted for partial runs. No code changes; the full test suite (1339 passed, 5 skipped) is unaffected.
- PR #227: Fixes the docs-agent's page-authoring loop so a nightly run cuts its work at a PR boundary instead of an arbitrary page-batch index. Previously the CCE-109 time-budget check fired at any batch index, and the at-least-one-progress escape hatch (`i > 0`) operated per page-batch rather than per PR. When the oldest PR in a run's window fanned out to more page batches than the time budget could author, the run split that PR's batch group on every single run and never finished authoring it — so the baseline cursor could never advance past it (observed on the ADIS host as a 20.6-day stall, always reporting `time_budget_no_advance_no_cursor`). The fix reworks the authoring loop's cut logic to operate at PR granularity: a run either fully authors a PR's page batches or defers the whole PR, guaranteeing forward progress every run.
- PR #231: The orchestrator now caches a merged PR's summary from pr-summarizer and reuses it on subsequent nightly runs instead of re-dispatching the agent against the same immutable merge commit. Previously, PRs left in the deferred/lookback window were re-summarized from scratch every night until the cursor advanced past them; measurements showed roughly 90% of a night's summarization work was repeat work on unchanged PRs.
- PR #232: Pinned node:test's TAP reporter explicitly (instead of relying on its default reporter selection) so that tests/templates/test_sdd_fidelity_gate_node.py reliably parses the pass/fail summary counts out of `node --test` output. Previously the parser used line-anchored regexes (`^\s*[ℹ#]\s*pass (\d+)\b`) that assumed node's plain 'spec' summary lines; when FORCE_COLOR is set (as it commonly is in agent/CI sessions), node injects ANSI escape codes before the summary tokens, which defeated the anchored match and caused the fidelity-gate JS suite check to report a parse failure even though the underlying suite passed cleanly (`pass 53`, `fail 0`, `returncode == 0`).
- PR #237: Fixes the citation_exists Tier-1 lint check so it resolves Python symbol citations (`path:symbol`) against any definition site — methods, nested functions, class attributes — not just top-level module definitions. Previously the linter only recognized symbols defined at the top level of a Python file, so citations to real, correctly-defined symbols nested inside a class or function were incorrectly reported as nonexistent, causing the authored page to be dropped by content-validator. Because a dropped page is not retried and the collection window still advances, this silently and permanently stranded documentation for legitimately-cited code.
- PR #238: The nightly orchestrator's watermark-advance logic is now cursor-backed on every code path, not just the time-truncated one. `deferred_pages_by_pr` and the `held_back` set are now computed unconditionally, and the cursor walk that limits the advance to the last fully-documented PR is entered whenever `time_truncated OR held_back` is true (previously it was nested only inside the `if time_truncated:` branch). A clean run's behavior is unchanged (full window-HEAD advance when nothing is held back); a run that is partial for a non-time reason (lint block, `page_author_invalid`, etc.) now advances only as far as the last PR whose pages all landed, instead of jumping to full window HEAD and silently discarding the undocumented window. Reason strings are now cause-dependent (`time_budget_*` vs `held_back_*`) to preserve existing operator-facing grep patterns and test assertions for the time-truncated family.
- PR #239: Fixed the internal_links Tier-1 lint rule so it no longer treats markdown links that are being documented as examples (verbatim link text quoted inside prose explaining a link-parsing function) as if they were real navigation links. The rule was blocking pages that legitimately quoted link syntax as illustrative content, most visibly a page documenting extractDocRefs — a function whose entire purpose is parsing markdown links out of CLAUDE.md — which was blocked twice for containing the exact example links it was explaining.
