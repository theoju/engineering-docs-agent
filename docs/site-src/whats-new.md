# What's New

## 2026-05-29T08:25:09.899829+00:00
- PR #63: Two documentation corrections in the install and setup materials: (1) README.md line 29 replaced the wrong secret name `ANTHROPIC_API_KEY` with `CLAUDE_CODE_OAUTH_TOKEN`, matching the actual secret the Claude CLI reads (the OAuth slot, distinct from console API keys); (2) `docs/setup-guide.md` line 38 corrected the manual trigger command from the non-existent `docs-agent-run.yml` to `docs-agent-nightly.yml`, which matches the actual workflow file in `.github/workflows/` and the README.
- PR #62: Adds `_write_step_summary(state, repo_root)` to the orchestrator runner to append a bulleted digest of `partial_reasons` to `$GITHUB_STEP_SUMMARY` when running inside GitHub Actions. The function is wired via a `try/finally` block at the top of `run()` so the digest flushes even on hard-fail paths (config invalid, state corrupted, `open_or_append_pr` crash). A shared `_format_partial_digest(partial_reasons)` helper is extracted and reused by the PR body composer, replacing the old semicolon-joined WARNING string with a bulleted list on both surfaces. Nine new tests cover the helper contract, OSError swallowing, hard-fail flush, and clean-path positive pin.
- PR #61: Splits the `markdown_hygiene` lint rule into two distinct rules: `markdown_hygiene_lang` (severity `warn`) flags missing language tags on code-fence opening lines, while `markdown_hygiene_structure` (severity `block`) catches unpaired fences and heading-jump defects that genuinely break MkDocs rendering. Both rules replace the old single `markdown_hygiene` entry in `TIER1_DEFAULT`. The `lint_runner.py` script-path derivation is updated accordingly, and three new tests cover each rule independently plus runner registration.
- PR #60: A one-line correction in docs/setup-guide.md replaces the stale ANTHROPIC_API_KEY environment variable reference (the pre-CCE-35 auth path) with CLAUDE_CODE_OAUTH_TOKEN, which is what orchestrator_runner.dispatch_subagent actually reads when invoking the Claude CLI. An inline note explaining the OAuth-vs-API-key distinction was added so new host operators do not need to cross-reference release.yml or docs-agent-nightly.yml to understand which secret to provision.
- PR #50: PR #50 (CCE-38) adds a fail-fast post-write verification layer to the bootstrap orchestrator. The main additions are: (1) `parse_frontmatter_strict` in `archive_indexes.py`, a stricter sibling that distinguishes bad YAML from absent frontmatter; (2) a new `description_quality` Tier-1 lint rule that enforces minimum word count and prohibits descriptions equal to the page title; (3) `dispatch_verified`, a wrapper around `dispatch_validated` that runs a caller-supplied post-write callback and deletes the target file on failure so the existing skip-if-exists idempotency gives free retry; and (4) `_BootstrapProgress`, which atomically writes a per-page progress file at `.engineering-docs-agent/bootstrap.progress.json` on every state transition. These are wired into `run_bootstrap_core` with a dry-run guard. 34 new tests bring the suite from 559 to 593 passing.

## 2026-05-29T04:34:35.184775+00:00
- PR #58: Adds a `_remote_already_processed_window(repo_root, branch, our_head_sha) -> bool` helper to `scripts/orchestrator_runner.py` that detects same-hour duplicate runs before any subagent is dispatched. The helper fetches `origin/<docs-agent-branch>` and reads its committed `state.json` via `git show`; it returns `True` only when the remote branch's `last_successful_run.head_sha` strictly equals the current run's HEAD SHA. A new call site in `_main()` exits 0 with a skip log line when the helper returns `True`, eliminating the working-tree collision (on `whats-new.md` and `state.json`) that caused the post-CCE-42 smoke-test 2/2 to exit 1. Every failure path — network error, absent branch, missing or corrupted `state.json`, schema drift — returns `False` so the runner proceeds normally. Five unit tests cover all documented failure modes. `skills/engineering-docs-agent/SKILL.md` is updated with a new state-transitions bullet and a renumbered procedure step.

No Python source changes; the only modified source file is the nightly workflow YAML. Two new internal spec and plan documents were also added under docs/superpowers/.

## 2026-05-27

### Publish the docs site to GitHub Pages

The docs site can now be published to GitHub Pages through a generic, Node-24-safe GitHub Actions deploy. The setup skill scaffolds a workflow that builds the site, writes `.nojekyll` so the artifact is served verbatim, and publishes it with `upload-pages-artifact` and `deploy-pages` — replacing the legacy Jekyll build that crashed on `{{` and `{%` sequences in source markdown. Non-MkDocs hosts can point it at a custom `build_command` and `site_dir`. See the Operations guide "Publishing to GitHub Pages" for the full flow.
