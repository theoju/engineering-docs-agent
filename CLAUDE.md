# engineering-docs-agent — agent guidelines

A Claude Code plugin: eight specialized subagents turn merged PRs, commits, and Jira issues into a single nightly docs-update PR — voice-matched authoring, tiered linting, factual-accuracy checking, gap detection, and post-merge publish verification.

## Generic plugin — runs on ANY host repo (critical)

This repo ships a Claude Code **plugin**, not a one-off tool. Its skills — `/engineering-docs-agent:engineering-docs-agent` (the nightly docs-PR runner) and `/engineering-docs-agent:engineering-docs-agent-setup` (scaffolds the docs site) — run against **arbitrary host repositories**. This repo is simultaneously the plugin's source _and_ one dogfood host; never conflate the two.

Design every capability (S/D/API/M/C and the orchestrator) **generic-first, convention-optimized**:

- **Behavior is driven by detection and config, never by hardcoded paths.** `scripts/`, `agents/schemas/`, `docs/superpowers/{specs,plans}` are _this host's_ layout — they are examples in fixtures and defaults, never assumptions baked into capability code. Read inputs from the `site:` config block (`sources`, `extractors`, `docs_dir`) and from `setup_discover.py` detection.
- **Degrade gracefully.** When a host lacks a convention (no specs/plans, no Python package, no OpenAPI schema, no decision sources), the affected capability **skips or falls back cleanly** — it never errors and never emits an empty artifact. Detection drives the path taken.
- **Markedly better on Claude Code / superpowers repos** that carry `docs/superpowers/{specs,plans}`, but **nothing hard-requires that convention.**
- **Tests use fixtures that represent arbitrary hosts**, not this repo's tree. A capability that only works because it found this repo's own directories is a bug.

## Jira context

All Jira work for this project lives in:

- **Instance:** `https://designitright.atlassian.net`
- **Project:** Claude-Code-Extensions
- **Key prefix:** `CCE`

Every branch and PR for this repo should reference a CCE issue:

- **Branch naming:** `<type>/CCE-<number>-<short-slug>` (e.g. `feat/CCE-12-jira-input-wiring`, `fix/CCE-7-empty-path-guard`)
- **Commit messages:** include `CCE-<number>` in the subject line or trailer when the change implements a specific ticket. Hardening / refactor commits that close multiple tickets may list them in the body.
- **PR titles:** prefix or include `CCE-<number>` so the Atlassian GitHub integration auto-links.

The `/ship` skill's Jira stage uses `extract-jira-key.sh` to pull the key from the branch name or the first commit subject. Keep the format above so it lands automatically.

## Voice & style

This file is read by the docs-agent's `load_voice_samples` helper (per `scripts/state_io.py`). Keep prose:

- Direct and concrete. Avoid hedging ("perhaps", "might consider", "it could be argued").
- Second person ("you", "your") when addressing the reader. Third person ("the orchestrator", "the runner") when describing system behavior.
- Short paragraphs. One idea per paragraph.
- Code names match `file_path:line_number` for navigability.

## Plugin conventions

- All work happens on a feature branch off `main`. Direct commits to `main` are not allowed.
- Merge on a green _integrated_ suite, never on GitHub's "mergeable" flag (that only means no textual conflict). Before merging, merge the target branch into yours locally and run the full `python3 -m pytest` against the combined tree. With stacked branches, land the base first, then siblings one at a time, re-testing between each (`git fetch` before verifying — `origin/main` goes stale after an API-side merge).
- Shared helpers are contracts. Before changing the signature or behavior of a cross-capability helper (`archive_indexes.parse_frontmatter`, anything in `state_io.py`, `contracts.py`), `grep -rn` its callers repo-wide and update them in the same change; never let two branches refactor the same helper in different directions.
- Python: stdlib-first. New runtime deps require explicit justification in the spec.
- Tests: pytest. TDD for new behavior (failing test → implementation → green). All tests use the fixture-driven dry-run path; the production Claude CLI dispatch is monkeypatched in unit tests.
- Subagent contracts: each agent's `.md` file in `agents/` defines the canonical input/output shape. JSON schemas in `agents/schemas/` codify the output shape. Dataclasses in `scripts/contracts.py` provide the typed view.
- Linting: the host repo's `lint.tier1: default` setting enables the full Tier-1 rule set (`TIER1_DEFAULT` in `scripts/lint/lint_runner.py` — count it there rather than hardcoding a number here). Tier-2 and Tier-3 are opt-in per rule.
- Config invariant: every `docs.lens_paths` entry must be covered by at least one `docs.agent_editable_paths` glob (validated at load by `_validate_lens_paths_are_editable`). The editable glob may be narrower than the lens path (e.g., a sandbox sub-path of a top-level lens).
- **`actions/configure-pages@v6 enablement: true` does NOT bootstrap GitHub Pages on a first deploy.** Despite the field name and the action's docs. The workflow's `GITHUB_TOKEN` lacks the admin scope required to call `POST /repos/.../pages`; `permissions:` blocks can only restrict default-token scopes, never expand them. The plugin's `templates/workflow-pages.yml` therefore does NOT include this field; bootstrap is done by `skills/engineering-docs-agent-setup` step 6c calling `scripts/enable_pages.py` (which wraps `gh api -X POST repos/.../pages -f build_type=workflow`) with the operator's admin gh auth. The script handles 4 failure modes (201, 409, gh-missing, all-other) and always returns 0 — graceful fallback never blocks scaffolding. Reference: CCE-82 (2026-06-02); the originating incident was `theoju/claude-code-self-assessment` PR #121 / CCE-81. The plugin's own dogfood `.github/workflows/docs-pages.yml` was also cleaned in this fix.
- **`gh pr checks <N> --json` returns `name`/`state`/`bucket`, NOT `statusCheckRollup`/`conclusion`.** Any orchestrator or skill that polls checks must parse `c.state==='FAILURE' || c.bucket==='fail'` (or `state==='SUCCESS' || bucket==='pass'` for green). The non-JSON `gh pr checks` text output uses different vocabulary again (`pass`/`fail`/`pending`) — match by column, not by reusing JSON field names. Reference: CCE-83 meta-orchestrator plan iter-3 residuals (2026-06-03), Task 15 Step 2.
- **`gh pr view --json` prompts to subagents must demand raw JSON output.** Without the explicit instruction `"Return only the raw JSON output from gh pr view (no surrounding prose)"`, subagents wrap the JSON in markdown fences or commentary, and `JSON.parse` on the result throws. Either include that line in the prompt, or wrap parse in try/catch with a sentinel fallback. Same pattern applies to any `--json` consumer fed through a subagent — never assume model output of a CLI is parseable as-is. Reference: CCE-83 meta-orchestrator plan iter-3 residuals (2026-06-03), Tasks 16/17 Step 1.
- **Plan-step verification must use the actual consumer tool, not just filesystem checks.** When a plan step produces a published artifact — a markdown link inside a built docs site, a TypeScript import, a JSON Schema reference, an OpenAPI route — the verification step must invoke the tool that consumes the artifact (`mkdocs build --strict`, `npx tsc --noEmit`, `ajv validate`, etc.), not `test -f`. A filesystem path can resolve correctly on disk while violating the consumer's validity contract (e.g., mkdocs strict-mode rejects link targets outside `docs_dir`, regardless of whether `test -f` passes). Reference incident: ADIS PR #411 broke docker-push because Task δ.2's `test -f` verified the runbook existed on disk; the published link to it from `docs/site-src/ops/runbooks.md` failed `mkdocs build --strict`. Closed by PR #416. The cost of running the real consumer tool in a plan step is a one-off; the cost of a half-verified plan landing is a deploy outage.
- **docs-agent PRs auto-merge by default since CCE-101 (the CCE-89 D3 decision).** Eligible = non-partial AND zero fact-checker warnings AND no human commits on the PR; the runner polls `gh pr checks` (grace 120s for checks to register, 900s for them to settle — both bounded by the CCE-109 budget), squash-merges with branch deletion, then explicitly dispatches `publishing.build_workflow` (a `GITHUB_TOKEN` merge cannot fire `on: push` workflows — without the dispatch the site never redeploys). Since CCE-123 that dispatch forks on `publishing.ci_provider`: a non-github provider records an info-only `pages_dispatch_skipped: circleci_trigger_modeled_but_unvalidated` reason instead of a GH Actions dispatch (the real CircleCI trigger is stubbed behind `UNVALIDATED_AGAINST_LIVE_HOST`, symmetric with the CCE-63 verify seam). Absent `merge:` config = auto; hosts opt out with `merge: {policy: manual}`; setup asks every new host explicitly. Any skip/failure leaves the PR open with an info-only `auto_merge_*` reason — `state.json.last_successful_run` then advances only when the operator merges, and D2 auto-close sweeps superseded PRs. History: six stale PRs accumulated 2026-05-30→06-01 when merging was manual-only (head SHAs archived under `.engineering-docs-agent/stale-prs-archive/`); D1 body-enrichment + D2 auto-close shipped first, CCE-101 closed the loop. Spec: `docs/superpowers/specs/2026-06-10-cce101-merge-gate-design.md`.
- **`gap-detector` and `fact-checker` are ADVISORY agents: their dispatch failures are info-only and never flip `partial` (CCE-118 fact-checker, CCE-125 gap-detector).** Only the blocking pipeline (source-collector, pr-summarizer, page-author, content-validator, notifier) flips `partial` on failure, via `_record_dispatch_reasons(state, reasons, ok=<dispatch produced usable output>)`. An advisory agent's output only feeds a PR note (fact-checker → `fact_check_warnings`; gap-detector → "Gaps flagged"), and gap-notes are **not** in the CCE-101 auto-merge gate — so an advisory agent that merely "couldn't judge" must not degrade the run. CCE-125's mechanism: gap-detector's documented malformed-input fallback `needs_spec: null` is now a first-class "unjudged" value — `gap_detector.schema.json` types `needs_spec` as `["boolean","null"]` (still `required`); a validated null verdict records an info-only `gap_detector_unjudged` reason at the callsite and is **skipped** (never appended → excluded from "Gaps flagged" and the CCE-89 digest). Only PRESENT-`null` is downgraded: an **absent** `needs_spec` key / wrong non-null type / unparseable output still fails schema → still flips `partial` (the genuine-agent-malfunction signal is preserved). Two traps this touched: (1) when changing an agent's JSON schema, edit BOTH `agents/schemas/<agent>.schema.json` AND the canonical fenced block in `agents/<agent>.md` in lockstep — `tests/agents/test_schema_md_sync.py` asserts `json.loads`-equality — then regenerate the published contract doc with `python scripts/contracts_doc.py --repo-root . --config <host-config>` (never hand-edit `docs/site-src/api/contracts/*.schema.md`); (2) `dispatch_validated` returns the RAW dict, not the dataclass, so consumers use `.get()` and the dataclass type hint (`GapVerdict.needs_spec: bool | None`) is cosmetic at runtime — the schema is the real gate. The general `ADVISORY_AGENTS` unification (one explicit set covering both agents) is a deferred refactor. Spec: `docs/superpowers/specs/2026-07-23-cce125-gap-detector-unjudged-advisory-design.md`. Reference: CCE-125 (2026-07-23).
- **A failed GitHub App-token step degrades the run to `partial`; it must never kill the job (CCE-127).** The workflow runs `actions/create-github-app-token` under `continue-on-error: true` and exports `steps.app-token.outcome` as `DOCS_AGENT_APP_TOKEN_STATUS` at **step** scope (job-env cannot reference `steps.*`). `orchestrator_runner.run` records a blocking `app_token_unavailable` reason for the literal `"failure"` only — `"skipped"` (the bare-host path, no `DOCS_AGENT_APP_CLIENT_ID`), `"success"`, and unset stay silent. Flipping `partial` reuses the existing `_maybe_auto_merge` interlock — **no new gate code for CCE-127 itself**, which reused what was already there — now chained, in order, as `merge_veto_reason` (matching `_MERGE_VETO_REASON_PREFIXES`, e.g. `app_token_unavailable`), CCE-144's own new `if blind: return skip("blind_run")` gate (unconditional, ahead of the carve-out below), and CCE-140's `if partial and not advance_cursor_backed` — which is the point: a PR built on the fallback `GITHUB_TOKEN` never fires host CI, so zero registered checks would otherwise read as "nothing failed" and auto-merge unvalidated docs. Placement of the env read is load-bearing: after the `current_run` dict literal (`add_partial` creates a stub that the literal would overwrite, silently swallowing the reason) and before the auto-merge decision. Four traps this touched: (1) **`continue-on-error` is what makes the `||` fallback reachable at all** — GitHub evaluates `steps.app-token.outputs.token || secrets.GITHUB_TOKEN` only for a _skipped_ step; a _failed_ step aborts the job before the expression is reached, so CCE-80's fallback was dead code on the failure path for two months. Two mechanisms are required and either alone is inert. (2) **Export `outcome`, never `conclusion`** — `continue-on-error` rewrites `conclusion` to `success`, so a `conclusion`-keyed export or test passes green while reporting a healthy mint for a run that had no token; that is worse than no fix, because it auto-merges with a clean signal. (3) **404 ≠ 401 when a token mint fails** — a 404 on `/repos/{owner}/{repo}/installation` means the JWT authenticated fine and no installation covers the repo (scope lost: App uninstalled, transferred, or repo-selection narrowed → **re-install**, credentials are fine); a 401 means the App or key is bad (→ rotate). The originating incident was an org transfer that deleted the installation, so `vars.DOCS_AGENT_APP_CLIENT_ID` and `secrets.DOCS_AGENT_APP_PRIVATE_KEY` needed no change. (4) **CI does not lint `templates/`** — `.github/workflows/actionlint.yml` runs bare `actionlint -color`, which searches `.github/workflows/` only, so template changes must be linted explicitly (`actionlint templates/workflow-run.yml`). That gap is plausibly how the template drifted from the dogfood in the first place. Meta-lesson on `_TEMPLATE_ONLY_DIVERGENCES` in `tests/templates/test_workflow_run_parity.py`: three entries recorded the dogfood _lacking_ a template safety property, justified by "dogfood requires the App" / "dogfood uses only the App token" — both true, both irrelevant, because the step fails on _state_, not intent. Owning the credentials is not the same as their staying valid, and **documenting a divergence is not the same as accepting the risk** — writing it down converted an unexamined gap into an accepted one and stopped anyone re-examining it. That list is documentation-only and no test detects staleness, so audit it whenever a safety property lands on one side. Incident: 2026-07-23 → 2026-08-07, 15 consecutive failed nightlies each on `theoju/engineering-docs-agent` and `theoju/claude-code-self-assessment` (~30 runs), invisible because neither repo had `SLACK_WEBHOOK_URL` wired — the dogfood now carries it. Death alarm for pre-checkout failures is **CCE-128** (deliberately split: the draft assumed the tree is checked out when an `if: failure()` step runs, which is false before `actions/checkout`). Spec: `docs/superpowers/specs/2026-08-07-cce127-app-token-degrade-partial-design.md`. Reference: CCE-127 (2026-08-07).

- **Run `scripts/prune_merged_branches.py --apply` after every batch of `gh pr merge` calls in a session.** The local feature branch lingers as `[gone]` against origin after `gh pr merge --delete-branch`; left alone these refs accumulate and the workspace's branch list bloats to dozens of stale entries (the 2026-06-04 sweep recovered 13 such refs). The helper is dry-run by default — re-run with `--apply` to delete. It safe-skips `[gone]` branches with unmerged commits (typical pattern when an operator amended without pushing); use `--force-unmerged` only after manual review of the skip list. It also catches `worktree-*` orphan refs left by the Workflow tool's `isolation: 'worktree'` mode (force-delete by default for that bucket — the worktrees are throwaway scratch by design). The actual prevention surfaces are tracked separately: CCE-99 for the `/ship` post-merge hook (user-global skill edit, non-durable) and CCE-100 for upstream worktree-harness cleanup. Reference: CCE-90 (2026-06-04).
- **A merged CCE PR auto-transitions its Jira issue(s) to Done** via `.github/workflows/jira-transition.yml` (CCE-103). The PR **title** is the single source of truth — `extract_keys` in `scripts/jira_transition_on_merge.py` pulls `CCE-\d+` keys from it; body/branch/commit mentions are deliberately ignored (so a PR body that references other tickets does not close them). The helper is stdlib-only (`urllib`), comments-then-transitions (a failed transition leaves a visible "Closed by PR" comment on a still-open ticket for the next triage), and fails loud (workflow exits non-zero → red ✗ + email) — the PR is already merged, so noisy failure cannot block delivery. Reads use Jira REST v3; the comment POST uses v2 (it accepts a plain string body; v3 requires ADF). Dry-run via `workflow_dispatch` (`dry_run` default true) exercises the read path with zero writes. Repo-local hygiene only — NOT scaffolded onto host repos (plugin promotion deferred until demand; `JIRA_BASE_URL` would move to config then). Reference: CCE-103.
- **Docs cite code line-free: `` `path/to/file.py` `` or `` `path/to/file.py:symbol` `` (`file.py:Class.method`), never `path:line`.** Citation _existence_ is a deterministic lint concern, not a fact-checker one. `citation_exists` (Tier-1 **block**) recognizes the `:symbol` grammar and verifies the symbol is actually defined in the cited file — a confabulated symbol fails the build; `citation_line_free` (Tier-1 **warn**, advisory) flags any surviving `:line` pin. The `fact-checker` agent is scoped to **behavioral** truth only and must NOT emit `contradiction` for citation location/line drift (line drift is constant noise; that concern is owned by the lint). Migrating a stale `path:line` to its enclosing symbol is dangerous: it can resolve to a real-but-_wrong_ symbol that passes the existence lint yet contradicts the prose, reading as authoritative — worse than the opaque line. The one-time migration (`scripts/migrate_line_citations.py`, AST-based) therefore keeps `:symbol` only when the page's own prose corroborates it (symbol backticked in prose, or it is the cited file's namesake) and downgrades everything else to bare `path`. Distinct from C1's `<!--pin:TOKEN-->` line-pin mechanism (`scripts/verify_citations.py`), which is unaffected. Spec: `docs/superpowers/specs/2026-07-18-cce122-stable-code-citations-design.md`. Reference: CCE-122 (2026-07-22).
- **`tests/scripts/` must NOT be a package — no `__init__.py`.** `scripts/` is a PEP 420 implicit namespace package (no `__init__.py`). Under pytest's prepend import mode a `tests/scripts/__init__.py` gets registered as the top-level `scripts` package, shadowing the real one in `sys.modules`, so any later `from scripts.lint... import` in another suite fails with an order-dependent `ModuleNotFoundError` (surfaced as two flaky `test_lint_runner` failures). Import scripts modules in tests via the dotted namespace path (`from scripts.lint import citation_exists`), never by `sys.path.insert`-ing the scripts dir and importing the module bare — that mutation poisons namespace resolution for the rest of the session. Reference: CCE-122 (2026-07-22).
- **Release & rollback ops live in `docs/runbooks/release-and-rollback.md`.** Cutting a version tag, the two release clocks (`release.yml` validation ~5–10 min vs tag-pinned host pickup up to ~24h at the next 07:07 UTC nightly), rolling back a bad tag (`gh release delete <tag> --cleanup-tag --yes`), and tag-cut-misfire recovery are documented there. The one-time CCE-80 host migration is in `docs/runbooks/cce80-host-migration.md`. Reference: CCE-86 (2026-06-09).
- **Any orchestrator composing the superpowers SDD pattern MUST verify subagent self-reports against external authority before the next step — declare-then-discharge, never trust-the-report.** An implementer can return `status: DONE`/`DONE_WITH_CONCERNS` with no on-disk edits; the spec-reviewer then passes on the unchanged tree, and the task is marked complete on phantom work. Root cause: the reviewer validated _intent_ (is the plan sound?), not _execution_ (did it run?).
  - **Organizing principle.** Trust nothing the subagent authors about its own work (prose OR JSON). A structured field is trustworthy only if it dereferences to external state: `changed_files` → diff against git; `commit_sha` → check it out; `verify_cmd` → run it; `summary` → advisory only.
  - **The fix is a verification ladder.** The plan declares per-task post-conditions; the gate discharges the strongest **fidelity tier** the task declares (these are verification-ladder tiers — distinct from the lint Tier-1/2/3 above). Canonical doc `docs/superpowers/templates/sdd-fidelity-gate.md`; dependency-injected, unit-tested reference implementation `docs/superpowers/templates/sdd-fidelity-gate.mjs` (JS suite gated in pytest via `tests/templates/test_sdd_fidelity_gate_node.py`; doc/impl drift caught by `tests/templates/test_sdd_fidelity_gate_template_sync.py`).
  - **Tier 0 (always).** Pre-dispatch baseline diff of `git status --porcelain` + `git log --since` against `task.expected_touch_paths` (catches no-op; baseline-attributed so a tree already dirty from a prior task can't mask it), plus a claimed-vs-observed cross-check (the implementer's `changed_files` must appear in the git delta — a cooperation-dependent over-claim check using git alone, not full forensic verification).
  - **Tier 1 (if `task.verify_cmd`).** Run the real consumer tool (catches wrong-op). This is the line-above "actual consumer tool, not `test -f`" invariant applied per-task.
  - **Tier 2 (if `task.red_green`).** Assert the discriminating check fails pre-implementation and passes post (catches no-op + wrong-op + already-green).
  - **Reviewer gate.** After each `concur`: `findings: []` (explicit empty) vs missing-`findings` (silent no-op); an _advisory_ `evidence.files_read` vs `task.review_targets` check (self-authored — catches the lazy reviewer, not the lying one); and a `concur`+`low_confidence` contradiction halt re-checked on every retry. The composed `runFidelityLadder` signals a pass only via `concurred === true` — `halted === false` alone is not a pass.
  - **Layered, not atomic.** Tiers differ by host-requirement and cost. Tier 0 needs only git, so **ship it first** for universality, and it independently closes the _no-op_ mode — but it is NOT sufficient alone: the _didn't-look_ rubber-stamp mode stays open until the reviewer gate, and _wrong-op_ until Tier 1/2. Read "ship Tier 0 first" as "Tier 0 is the universal floor," never "Tier 0 is enough."
  - **Graceful degradation is the selection logic.** A bare host gets Tier 0 (pure git, universal); a rich host lights up Tiers 1–2 automatically, no errors on the bare path — same generic-first mandate as the rest of the plugin.
  - **Residual gap.** The reviewer "did you actually read it" case needs the harness to expose per-subagent tool-call logs (see the template's **Known limitations**); `evidence.files_read` is the advisory interim.
  - **Provenance & tickets.** 2026-06-04 B11 incident (CCE-77 ship-validator task), patch at `~/.claude/orchestrator/detached-changes/B11.patch`. Umbrella CCE-92 (children CCE-93 implementer/Tier-0 gate + CCE-94 reviewer gate + CCE-95 upstream PR to `obra/superpowers`; Tiers 1–2 are convention-only extensions, no separate ticket). Until CCE-95 lands, every inline Workflow script that composes the SDD pattern copies the template's ladder into its per-task loop.
- **A blind run exits non-zero, freezes the watermark, and cannot auto-merge (CCE-144).** `partial` conflated two conditions with opposite meanings. The split: **blind** = the run CONSUMED input it could not process (`source_collector_*`, `pr_summarizer_*`, `content_validator_invalid`, `notifier_invalid`, `app_token_unavailable`); **degraded** = the run HELD BACK what it could not process (every `time_budget_*` reason — `time_budget_exceeded`, `time_budget_advance_out_of_window`, `time_budget_no_advance_no_cursor`, `time_budget_no_advance_unanchored_deferred` — plus `lint_block*`, `unsafe_page_path`, `unknown_lens`, `page_author_invalid`, `gap_detector_invalid`, `deferral_skip`). `partial` remains the union. Classification is by CALL SITE, never by reason string — `schema_invalid:` is emitted by three call sites carrying two different classifications: source-collector (blind, by default) versus page-author and gap-detector (both `degraded=True`). The complement writer (the only writer of `deferred_pages_by_pr`) is what decides which — ~~but it only holds a PR out of the advance on the time-truncated path; a non-truncated run advances straight to window HEAD without reading `deferred_pages_by_pr` at all, so the sole protection for a degraded failure there is CCE-140's merge gate plus merge-as-promotion~~ — **this was true when CCE-144 shipped and is the defect CCE-151 fixed; see the CCE-151 entry below. The complement writer now holds a PR out of the advance on BOTH paths.** `page_author_invalid` is degraded because an unlanded batch holds its PR out of the advance cursor, while `content_validator_invalid` is blind because those pages are already in `landed_batches` and the cursor walks past them regardless. `state_io.add_partial` gains `degraded=True` as the opt-out and stays the single writer of `partial_reasons`, `blind`, and `blind_reasons`; **blocking reasons are blind by DEFAULT** so an unclassified new failure mode is loud, not silent. Three consumers read the flag: `_exit_code` (1, sharing the code `run` already returns when the PR can't be opened), `_should_advance_watermark`, and `_maybe_auto_merge`'s `blind` gate. Four traps: (1) **the auto-merge gate is not `if partial`** — CCE-140 narrowed it to `if partial and not advance_cursor_backed`, so a blind + time-truncated + cursor-backed run reaches the merge path; the blind gate goes ahead of that carve-out, and gating on the computed flag rather than extending the one-entry `_MERGE_VETO_REASON_PREFIXES` allowlist closes the class instead of one member. (2) **The `time_budget_exceeded` sites MUST stay degraded** — marking them blind turns every truncated run red and freezes its advance, deleting the cursor-backed advance CCE-140 exists to produce and reinstating the CCE-109 doom loop permanently; the guard is `tests/orchestrator/test_time_budget.py`, `tests/orchestrator/test_deferral_skip.py`, and `tests/orchestrator/test_cursor_backed_merge.py` — flipping one `time_budget_exceeded` site to `degraded=False` fails **19 / 2 / 19 / 20** of their tests for the admission / authoring / fact-check / gap-check site respectively (all four flipped together: 20, not the sum — the same tests catch several sites). Re-measured 2026-08-21; the previously-written flat "22 assertions" matched no site and conflated tests with assertions. **The number that matters is the 2.** The authoring site is the one a real run trips most often, and it is the most thinly guarded of the four — treat a change near it as effectively untested and add coverage before touching its classification. `tests/orchestrator/test_blind_run_interlocks.py` pins a narrower thing: given `blind=False` as a literal, `_maybe_auto_merge`'s own gate precedence still reaches the CCE-140 carve-out rather than stopping at the blind gate — it does not exercise the upstream classification at all. (3) **The `if time_truncated:` block goes inside the watermark guard** — it mutates `last_successful_run` in place, so left outside it lets a blind run write `window_head_sha` into the previous run's cursor. (4) **`_record_dispatch_reasons` is the single path for all seven agent dispatches**, so the blind default reaches all of them at once; page-author and gap-detector pass `degraded=True`, and each agent additionally has a direct `add_partial` fallback for when the dispatch reported nothing — both paths must carry the same classification or a failure changes colour depending on whether it managed to explain itself. `tests/orchestrator/test_classification_coverage.py` requires an explicit classification kwarg at every blocking call site (a registry was prototyped and rejected — its keys collide in `verify_runner` and it decays). Incident: runs `31472240064` and `31579090583` both reported `conclusion: success` with every subagent rate-limited; PR #215 then merged a watermark advance past #211/#212/#213, whose content is permanently undocumented. - **The watermark advance is cursor-backed on EVERY path, not just the time-truncated one (CCE-151).** CCE-140 built a cursor walk that advances only as far as the last PR whose pages all landed, and CCE-144 built the complement writer that decides which PRs those are — but the whole apparatus sat inside `if time_truncated:`. The `else` branch assigned `advance_sha = current_run.head_sha` (full window HEAD) without reading `deferred_pages_by_pr` at all, so any run that was partial for a NON-time reason — a lint block, a `page_author_invalid`, anything degraded — consumed its whole window regardless of what it documented. The cursor is consume-once: a window it skips is never re-read. **The fix is structural, not a new veto.** `partition_deferrals` and the `held_back` set are now computed unconditionally and the walk is entered on `time_truncated or held_back`; the `else` branch keeps the plain window-HEAD advance and is gated on `held_back` being empty, so clean-run behaviour is byte-identical. Four traps. **(1) The obvious fix is wrong and actively harmful.** Extending `_should_advance_watermark` to refuse when `partial and not advance_cursor_backed` freezes the cursor on _every_ lint block and reinstates the CCE-109 doom loop that CCE-140 exists to prevent — one permanently-unlintable page wedges the baseline forever. The cursor must still MOVE, just not past undocumented work; `tests/orchestrator/test_cursor_backed_merge.py::test_mixed_window_advances_to_the_last_fully_documented_pr` is the guard, and it asserts `advanced != base` for exactly this reason. **(2) Hoisting the READ is not enough — `partition_deferrals` had to move too.** With `still_deferred` defaulting to `[]`, every non-truncated run silently CLEARED the deferral counts of the PRs it held back, so no PR could ever accumulate enough deferrals to reach the skip threshold. That release valve is what stops trap 1 from recurring by another route; hoisting only the `deferred_pages_by_pr` read arms the freeze without arming the escape. **(3) Merge-as-promotion was never the containment it reads as.** The pre-fix reasoning held that an operator merging by hand is the safety check. Merging is all-or-nothing: PR #203 on the host carried a recovered page AND a poisoned advance in one diff, so the operator's only options were to accept both or lose the recovery. A gate that cannot be applied to half a PR is not a gate on the half that is wrong. **(4) The reason strings are now cause-dependent.** The walk serves two causes, so `_rsn` selects `time_budget_*` vs `held_back_*`. The `time_budget_*` family must stay byte-identical — `test_time_budget.py` / `test_deferral_skip.py` assert those exact strings and the CCE-109/CCE-140 runbooks tell operators to grep for them. Neither family is in `_MERGE_VETO_REASON_PREFIXES` (one entry, `app_token_unavailable`), and both sites keep `degraded=True`, so CCE-144 classification is unchanged. **Diagnostic reflex:** if the nightly is green, `partial: true`, and the baseline moved anyway, print `deferred_pages_by_pr` and `held_back` before suspecting the linter — a populated `deferred_pages_by_pr` next to a HEAD-valued baseline is this bug, not a page-authoring one. Incident: runs `32460602658` and `32495019606` (2026-08-21, `theoju/claude-code-self-assessment`) each blocked a page on lint and advanced anyway; the second consumed the very window the first had stranded, and recovery needed a hand-written baseline rewind. Reference: CCE-151 (2026-08-21), which also inverted `test_state_advancement_invariant.py::test_partial_run_via_lint_block_advances_state` — CCE-40 §7 row 4's "a partial run still advances" now means "advances past what it documented", not "advances to HEAD".
- **Shortened citations are DETECTED, never repaired (CCE-141).** `page-author` sometimes shortens an already-resolvable citation — the ADIS page cited `.claude/skills/connector-builder/references/checklist.md` at three sites and the rewrite emitted bare `references/checklist.md`, which `citation_exists` correctly blocked. Post-CCE-140 that is not a stall: the deferral skip abandons the PR and **the page is silently never written**. **What ships is diagnosis only.** `scripts/citation_repair.py` reports the tracked file such a citation was most likely shortened from and stops: `diagnose()` returns `[(cited, candidate, confidence)]`, there is no `Path.write_text` in the module, and **there must never be one** — do not restore `repair_text` or `rewrite_token`. Wired as `_diagnose_citation_paths` (`scripts/orchestrator_runner.py:1602`, called at `:2612` **after** the whole authoring loop and **above** the lint-block revert, so it reads the same finished tree `citation_exists` is about to read), `info_only`, one digest line per blocked citation. `diagnose` returns **four** labels — `candidate_in_run_inputs`, `suffix_match_only`, `ambiguous` (candidates capped at `_AMBIGUITY_CAP`, then `(+N more)`), `no_candidate` — but only **three** reach the digest: `no_candidate` is dropped, because its own evidence says the token is not a shortening of anything in the repo and `lint_block` already names those paths with severity. The other two used to `continue` **silently**, so a page blocked on two candidates produced no line at all while the single-candidate case was loud; the digest is now a census of blocked citations rather than a highlight reel. **Name the labels for what they measure.** They were `corroborated`/`uncorroborated` until round 5 — names that read as *confirmed* while the status was granted by batch membership alone. `candidate_in_run_inputs` says only that an input to this run other than the authoring agent already named that file (rung 1: the linter's own `set(extract_citations(prior_text)["paths"]) & files` on edits; rung 2: the batch's `grounding`/`source_paths`, which is **not** orchestrator-authoritative but the `source-collector` LLM subagent, bounded only by the candidate having to be a **tracked** file). `suffix_match_only` says it rests on the suffix match alone. `_is_excluded` (a bool) still suppresses what `check_path` declines to CHECK (exempt tokens, reserved `example/`, gitignored); the candidate-side half of that machinery is gone with the rewrite. **A digest nobody can read is not a digest.** Findings are bounded twice — `_CITATION_FINDINGS_CAP` per page and `_CITATION_RUN_FINDINGS_CAP` per run — and both report what they withheld. Bounding one page and calling the digest bounded was the half-measure: `_format_partial_digest` joins every reason unconditionally, so N pages x 10 findings x ~950 bytes clears GitHub's 65,536-byte PR-body limit at roughly seven pages. **One pathological token costs only itself** — `_resolves` reaches `(repo_root / rel).exists()` and pathlib re-raises OSError for errno values outside its ignored set (ENAMETOOLONG among them), which discarded the whole page's `findings` list, so the per-citation body is wrapped. **Known blind spot, deliberately unfixed:** `_resolves` accepts an on-disk same-run sibling while `suffix_candidates` iterates `git ls-files` alone, so a citation shortened to a page this run just wrote names a **tracked decoy elsewhere in the tree** instead of the real target. Widening the candidate universe to untracked disk state is exactly the region-the-linter-does-not-verify class below; the cost is bounded because nothing acts on the label. Pinned by `test_a_same_run_untracked_sibling_is_a_known_blind_spot`. **One path breaks the info_only rationale and info_only is still right:** under an `archive-index` section CCE-124 downgrades `citation_exists` to `warn` and the revert fires only on `block`, so an archive page ships with its shortened citation and emits no `lint_block` at all — there the advisory is the only signal, which argues for keeping the line, not for promoting it. **Repair was built, reviewed four times, and withdrawn.** Four adversarial rounds produced four Criticals and every one was the same class in a new disguise: **repair moved a citation into a region `citation_exists` does not verify, so a BLOCK became a silent PASS and the pointer stopped being checked even after the file it named was deleted** — `git rm` the target and `check_path` still answers `(True, 'ok')`. Round 1: uniqueness never established the token was a *shortening* (the only entry condition was "does not resolve," which is the confabulation population the linter exists to block; **2086** unique-match non-resolving tails against **887** tracked files). Round 2: rung 1's raw substring scan corroborated fenced/URL/comment mentions the linter never validated. Round 3: the candidate blacklist missed unparseable tokens (`app/(marketing)/guides/setup.md` — `_REPO_PATH_RE` admits only `[\w.\-/]`) and the mkdocs build dir. Round 4 is the one to picture, because it is the fix for round 3 reproducing round 3's defect: the gate's own `_resolves_absent` asked "would this still resolve if the file were gone?" by running `_resolves` against an **empty temp repo root** — which deletes not one file but every file. All three existence arms are `X in files or (repo_root / X).exists()` (`scripts/lint/citation_exists.py:456-468`), so the on-disk half of all three went blind at once; a candidate that resolves through an untracked on-disk `docs_dir` sibling then read as "safe, verified by its own existence" and the gate **admitted** it. **Two measurements decided it, both re-derived 2026-08-21 at `85d5cdc`.** (a) **Zero firings across the whole archived production record.** `.engineering-docs-agent/stale-prs-archive/` holds 41 PRs, **19** carrying a `cites nonexistent path` block over **15** distinct blocked citations; against today's 887 tracked files, 5 now resolve via the CCE-139/145 `docs_dir` branch, 10 have no candidate at all, and **0 have a unique suffix match** — zero *before* corroboration is even consulted. (b) **Disabling it entirely left the suite green.** `if False:` at the production call site in a detached worktree gave **1531 passed / 4 skipped**, byte-identical to that worktree's baseline: not one test exercises the feature through the path production uses. **The transferable lesson is about escalating mechanism.** The guard grew every round — suffix match, then corroboration, then linter-validated corroboration, then a four-mechanism gate that fabricated an impossible-filename **twin** to ask the linter a hypothetical about a file that cannot exist — and the defect came back each time in a new place. `superpowers:systematic-debugging` names it: 3+ fixes each revealing a new problem in a different place is **not a failed hypothesis, it is a wrong architecture**; stop and question fundamentals rather than attempt fix #4. Fix #4 produced Critical #4. The fundamental was not any guard but the decision to **mutate a page the linter already blocked** — the set of regions the lint does not verify is open and discovered incrementally, so it cannot be enumerated from inside the module doing the mutating. A page that is never rewritten cannot be corrupted that way: deleting the rewrite deleted the class, not four instances of it. When the Nth fix is structurally more complex than the (N-1)th and the defect keeps returning somewhere new, delete the capability that hosts the class. **Never claim a repair is "provably correct"** — retired in Revision 2, and the last surviving assertion of it (an embedded `CLAUDE.md` draft at `docs/superpowers/plans/2026-08-21-cce141-citation-path-repair.md:838`) was retired in place. **Given up, honestly:** the automatic rescue. A recoverable shortened citation is no longer fixed and re-checked — the page blocks, the PR is abandoned, a human reads the digest. That is a real regression against the ticket as written, and it costs **nothing that was ever measured** (see (a) and (b)); the prospective loss is weighed against four demonstrated BLOCK→PASS corruptions that no layer below repair catches. **Diagnostic reflex:** if anyone proposes rewriting a blocked page again, the question is not "which guard is missing" but "which region of the lint have we not found yet" — and that question has no bounded answer.
