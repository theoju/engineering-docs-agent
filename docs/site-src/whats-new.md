# What's New

## 2026-06-01T19:05:37.077989+00:00
- PR #91: Migrated the docs-agent-nightly CI workflow from the deprecated `app-id` input to `client-id` on `actions/create-github-app-token@v3`, and re-classified `JIRA_EMAIL` from a Repository Secret to a Repository Variable. The preflight helper (`scripts/preflight_host.py`) gained a `variables_from_workflow` function and a `Variables checklist` section in its pre-run report. User-facing setup and operations docs were updated to split a combined Secrets table into separate Secrets and Variables sections, reflecting that `JIRA_EMAIL` no longer lives under `secrets.*`. A guard test (`tests/ci/test_workflow_auth_tier.py`) was added to prevent regression to the old `app-id`/`secrets.JIRA_EMAIL` input names. Client ID format handling was also reconciled for both pre-2024 (`Iv1.xxx`) and newer (`Iv23li...`) GitHub App styles.
- PR #89: The markdown_hygiene_structure linting rule was generating false-positive heading-hierarchy violations whenever a `#`-prefixed line appeared inside a fenced code block. The fix identifies all fenced-block ranges by pairing FENCE_RE matches into (start, end) spans, then skips any HEADING_RE match whose character offset falls within one of those spans. The change is a 13-line surgical update to `check_path()`, accompanied by 39 lines of new regression tests in the lint test suite.
- PR #88: The orchestrator runner's git staging logic was refactored to extract a `_stage_docs_run_changes(repo_root)` helper that explicitly excludes `.docs-agent-plugin/` from `git add` using a pathspec exclude pattern. Previously, running `git add .` from the host repo root caused Git to pick up the nested plugin checkout as a gitlink, contaminating every nightly host PR with an unwanted submodule reference. The setup skill was also updated to instruct hosts to add `.docs-agent-plugin/` to their `.gitignore`, and a new test suite covering gitlink exclusion was added.
- PR #87: The content-validator subagent was invoking `python scripts/lint/lint_runner.py` relative to the host repo root, but when the plugin is vendored at `.docs-agent-plugin/scripts/` in CI all Tier-1 lint rules crashed and the orchestrator surfaced `lint_block` in `partial_reasons`. This PR fixes the path resolution by having the orchestrator pass `_PLUGIN_ROOT` in the dispatch payload as `plugin_root`, and updating the agent contract to interpolate `<plugin_root>` in the lint invocation command. Supporting spec and plan docs were added, a pipeline integration test covers the new payload field, and one line was added to `orchestrator_runner.py`.
- PR #84: Adds `docs.framework: none` as a valid, first-class configuration value for the engineering-docs-agent plugin. Previously, hosts without a build framework had to either omit the key or accept coercion to mkdocs; now they can explicitly declare `framework: none`. The `framework_build` lint rule skips gracefully with a clear reason when this value is set, and `preflight_host.py` writes `framework: none` directly instead of overriding it. The config JSON schema (`templates/config.schema.json`) now accepts `none` alongside existing framework identifiers. New tests cover the lint skip path, schema validation, and preflight write behavior.
- PR #83: PR #83 adds five additive changes to prepare the engineering-docs-agent plugin for onboarding `theoju/claude-code-self-assessment` as its first JS/TS host. A `js_docusaurus` test fixture is added to cover the new detection path. `templates/workflow-run.yml` receives a minor fix. Accompanying plan, design spec, and user runbook docs are committed to the superpowers plans/specs tree.
- PR #82: This PR adds plugin-side scaffolding to onboard `theoju/advanced-data-import-system` as the first hybrid-CI (CircleCI) host of the engineering-docs-agent. - PR #81: Audited the §8 state-advancement invariant following the durable-state (CCE-40) and subagent-forensics (CCE-41) changes. ## 2026-05-29T20:18:08.098558+00:00
- PR #76: Removed the `paths:` filter from the `pull_request` trigger in `.github/workflows/actionlint.yml`. Previously, actionlint only fired when workflow files changed; now it runs on every PR. The `push: paths:` filter is retained so post-merge runs on `main` still only occur when workflows are actually modified.
- PR #75: Added a `_strip_code_fence` helper to the orchestrator's `dispatch_subagent` function that detects and strips markdown code-fence wrappers (` ```json … ``` `) from subagent output before strict JSON parsing. Previously, the existing `_rescue_json_object` path handled these fences correctly at the content level but appended `prose_contamination_rescued` to `partial_reasons`, causing a 'WARNING — Partial run' banner on every docs-agent PR where any subagent wrapped its JSON in fences (~19% of schema-bearing dispatches on the PR #69 run). The new helper short-circuits cleanly: if the raw output is a bare code fence wrapping valid JSON, strip and parse without marking partial. The rescue path remains intact for genuine prose contamination such as the CCE-15 SessionStart preamble. Two new documentation files (a plan and a spec) were added under `docs/superpowers/` as part of the change.
- PR #74: Applied four code-quality polish fixes to orchestrator_runner.py identified during the CCE-43 Stage 4 /ship review: extracted branch_name(now) into a named local variable (skip_branch), removed a dead KeyError arm from the _remote_already_processed_window except clause, replaced f-string brace-escaped JSON construction with json.dumps(), and replaced a silent third-branch fallthrough with an explicit raise AssertionError. Accompanying tests in test_open_or_append_pr.py were updated to cover the assertion guard.
- PR #73: The pre-flight validation of `CLAUDE_CODE_OAUTH_TOKEN` in both `release.yml` and `docs-agent-nightly.yml` GitHub Actions workflows was hardened from a single non-empty check to four layered checks: (1) empty/missing secret detection, (2) an explicit branch that rejects console API keys matching `sk-ant-api*`, (3) a first-10-chars diagnostic printout for unrecognised token shapes, and (4) a minimum length floor of 32 characters to catch truncated pastes. Expired OAuth tokens remain out of scope.
- PR #72: PR #72 adds a new GitHub Actions workflow (`.github/workflows/actionlint.yml`) that runs `actionlint` as a pre-merge gate on every pull request. The linter checks GitHub Actions context-scoping rules, expression syntax, and other workflow-layer constraints that plain YAML schema validation cannot catch. This closes the gap that allowed a `steps.*` reference at job-env scope to pass local validation but be rejected by GitHub's runtime validator with HTTP 422.
- PR #71: The nightly GitHub Actions workflow's 'Run summary' step replaced a fragile `cat ... 2>/dev/null | sed ... || echo "(no state)"` pipeline with an explicit `if [ -f ... ]` file-existence guard and a `jq -e '.'` one-liner. The old pattern masked `cat`'s non-zero exit code because pipe exit status is swallowed; the new form correctly falls through to the `(no state)` message only when the state file is genuinely absent, and also surfaces invalid JSON via `jq -e`'s non-zero exit.
- PR #70: Bumped two GitHub Actions in the docs-agent-nightly workflow from Node-20-bound majors to Node-24 majors: `actions/create-github-app-token` v1→v3 and `actions/upload-artifact` v4→v6. No workflow logic or behavior changed; only the action version pins were updated.
- PR #68: Added `JIRA_API_TOKEN` and `JIRA_EMAIL` as explicit job-level environment variables in `.github/workflows/docs-agent-nightly.yml`. The docs-agent-nightly workflow now surfaces these repo secrets into the runner environment so the source-collector can authenticate with Jira during each nightly run.
- PR #66: The `GH_TOKEN` GitHub App installation token reference in the nightly docs-agent workflow was moved from job-level `env:` to step-level `env:` on the "Run nightly authoring" step. GitHub's runtime validator rejects `steps.*` context expressions at job scope, so the token reference must live at the step level where it resolves correctly. The token itself (minted via `actions/create-github-app-token`) is unchanged; only its placement in the YAML moved.
- PR #65: The docs-agent-nightly GitHub Actions workflow was updated to mint a GitHub App installation token from the `docs-agent-bot` app instead of using the default `GITHUB_TOKEN` for git push and `gh pr create` operations. This single-file change to `.github/workflows/docs-agent-nightly.yml` ensures the nightly workflow authenticates as the app identity rather than as the built-in Actions bot.

Previously, partial reasons were tracked across 22 call sites but never written to stdout/stderr, and `save_persistent_state` intentionally strips `current_run` from the on-disk `state.json`. ## 2026-05-29T04:34:35.184775+00:00
- PR #58: Adds a `_remote_already_processed_window(repo_root, branch, our_head_sha) -> bool` helper to `scripts/orchestrator_runner.py` that detects same-hour duplicate runs before any subagent is dispatched. The helper fetches `origin/<docs-agent-branch>` and reads its committed `state.json` via `git show`; it returns `True` only when the remote branch's `last_successful_run.head_sha` strictly equals the current run's HEAD SHA. Every failure path — network error, absent branch, missing or corrupted `state.json`, schema drift — returns `False` so the runner proceeds normally. Five unit tests cover all documented failure modes. `skills/engineering-docs-agent/SKILL.md` is updated with a new state-transitions bullet and a renumbered procedure step.

## 2026-05-27

### Publish the docs site to GitHub Pages

The docs site can now be published to GitHub Pages through a generic, Node-24-safe GitHub Actions deploy. The setup skill scaffolds a workflow that builds the site, writes `.nojekyll` so the artifact is served verbatim, and publishes it with `upload-pages-artifact` and `deploy-pages` — replacing the legacy Jekyll build that crashed on `{{` and `{%` sequences in source markdown. Non-MkDocs hosts can point it at a custom `build_command` and `site_dir`. See the Operations guide "Publishing to GitHub Pages" for the full flow.
