- PR #103: Replaced the no-op `actions/configure-pages@v6 enablement: true` field in the docs-pages workflow template with a dedicated `scripts/enable_pages.py` helper that calls `gh api -X POST repos/.../pages -f build_type=workflow` at setup time. The setup skill's step 6c now invokes this script after writing the workflow file. The dogfood `.github/workflows/docs-pages.yml` and `templates/workflow-pages.yml` both had the now-misleading `enablement: true` block removed. Fourteen new CLI tests and two updated template tests were added.
- PR #99: Introduces a new leaf module `scripts/stderr_emit.py` that centralizes credential redaction and all stderr writes for the docs-agent pipeline. `state_io.add_partial` now emits a `docs-agent PARTIAL:` line on every call — including the dedup short-circuit path — so all partial-reason recordings appear on stderr regardless of whether the reason is newly appended or a repeat. `orchestrator_runner.py` routes its three `lint_block` direct partial-reason mutations through `add_partial`, deletes its local `_redact_credentials` in favour of the leaf module, adds `_emit_shutdown_dump` wired into the `run()` finally block to cover exit-0 partial runs, and converts ten raw `print(..., file=sys.stderr)` diagnostic sites to `emit_log`. `verify_runner.py` routes its two direct partial-reason writes through `add_partial`. Eleven acceptance criteria are locked by four new test files and an extended existing test (726 passed, 3 skipped).
- PR #98: Adds two anti-regression tests and documentation improvements for the orchestrator's `_stage_docs_run_changes` helper. The first test pins that mid-run mutations to tracked `.docs-agent-plugin/` content are dropped from the docs commit via a scoped `restore --staged` step and do not affect unrelated docs pages. The second test pins git bare-pathspec semantics — exact-match or prefix-followed-by-slash, not arbitrary prefix — by injecting a real gitlink with `git update-index --add --cacheinfo` and asserting it does not over-select sibling paths. A docstring paragraph and inline comment were added to `orchestrator_runner.py` documenting the probe-then-restore mechanism and scoping the symlink-not-a-directory assumption to all three git operations. A plan document capturing the full analysis was also added.
- PR #97: The orchestrator's `_stage_docs_run_changes` function was rewritten to fix a failure on host repos that gitignore `.docs-agent-plugin/`. The previous implementation used a negative pathspec (`:!.docs-agent-plugin`) that collided with `.gitignore` because git's pathspec layer promotes any explicitly named path to an 'explicitly mentioned' state, triggering its gitignore-aware safety check and returning rc=1. The fix replaces the pathspec with a three-step sequence: `git add -A .` (gitignore-aware staging), a diff probe, and a conditional `git restore --staged -- .docs-agent-plugin` to semantically revert the plugin directory's index entry to HEAD — preserving any pre-tracked content and `.gitmodules`-registered submodules. All three subprocess calls now propagate non-zero return codes and stderr instead of swallowing failures silently.
- PR #93: The orchestrator runner now surfaces all `open_or_append_pr` failure reasons to stderr in real time instead of silently accumulating them in state. Two helpers were added: `_record_failure()` replaces 7 silent `reasons.append()` call sites and immediately prints each reason to `sys.stderr` with `flush=True`; `_redact_credentials()` strips `https?://[^@/\s]*@` patterns before printing or recording to guard against auth tokens leaking via `git push` error output. `run()` also now emits any remaining redacted `partial_reasons` to stderr before returning exit code 1. Ten new pytest `capsys` tests cover every failure path, the redaction invariant, and a happy-path counterfactual.
- PR #91: Migrates the docs-agent-nightly workflow from the deprecated `app-id` input of `actions/create-github-app-token@v3` to `client-id`, and reclassifies `JIRA_EMAIL` from a Repository Secret to a Repository Variable (the correct tier for a non-credential value that is already visible in Jira comments and git commit author lines). Adds a CI guard test to prevent regression drift, extends `preflight_host.py` with variable-tier detection and a new `Variables checklist` section in its onboarding report, updates user-facing setup and operations docs to split the single Secrets table into separate Secrets and Variables tables, and adds the CCE-66 spec and phased migration plan documents.
- PR #89: The `markdown_hygiene_structure` lint rule was generating false-positive heading-hierarchy violations whenever a `#`-prefixed line appeared inside a fenced code block (e.g., a YAML comment such as `# comment` inside a triple-backtick block). A 13-line surgical fix to `check_path()` introduces `FENCE_RE`-based range detection: character offsets for all fenced blocks are collected first, and any `HEADING_RE` match whose offset falls inside one of those ranges is skipped entirely. Two new regression tests were added to `tests/lint/test_markdown_hygiene_structure.py` (5 existing + 2 new = 7 passing). No public API or import changes.
- PR #88: Fixed a bug where the orchestrator staged `.docs-agent-plugin/` as a git submodule gitlink (mode 160000) into every onboarded host repo's docs-agent PR. Replaced the bare `git add .` call in `scripts/orchestrator_runner.py` with a new `_stage_docs_run_changes(repo_root)` helper that uses git's exclude pathspec (`git add . -- ':!.docs-agent-plugin' ':!.docs-agent-plugin/**'`). Additionally updated the setup skill (`skills/engineering-docs-agent-setup/SKILL.md`) to instruct future host onboardings to add `.docs-agent-plugin/` to the host's `.gitignore` as a belt-and-suspenders guard. The old pattern masked `cat`'s non-zero exit code because pipe exit status is swallowed; the new form correctly falls through to the `(no state)` message only when the state file is genuinely absent, and also surfaces invalid JSON via `jq -e`'s non-zero exit.

## 2026-05-27

### Publish the docs site to GitHub Pages

The docs site can now be published to GitHub Pages through a generic, Node-24-safe GitHub Actions deploy. The setup skill scaffolds a workflow that builds the site, writes `.nojekyll` so the artifact is served verbatim, and publishes it with `upload-pages-artifact` and `deploy-pages` — replacing the legacy Jekyll build that crashed on `{{` and `{%` sequences in source markdown. Non-MkDocs hosts can point it at a custom `build_command` and `site_dir`. See the Operations guide "Publishing to GitHub Pages" for the full flow.
