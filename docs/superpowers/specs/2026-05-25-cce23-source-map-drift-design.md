## Why this exists

The umbrella spec names M as ADIS's `build_doc_source_map.py` ported into this plugin: read `source_files:` frontmatter from `site-src` pages, write the inverse map `source-path → [page-paths]`, and — when mapped source files change in a processed PR — surface the affected pages as **review-needed** so docs stay honest against code drift. The concrete map also feeds Phase 2 (C) for `file:line` citations.

This design covers the **full** capability: the map generator, a standalone drift detector, and the orchestrator `source-map` stage that surfaces drift.

## Generic-first mandate (per CLAUDE.md)

This runs on **arbitrary host repos**. Behavior is detection- and config-driven — `docs_dir` comes from config, the `source_files:` convention is opt-in per page, and source resolution uses the host's own tracked files. Absence of the convention (no page declares `source_files:`, not a git repo, a glob matching nothing) makes the affected step **skip cleanly** — never error, never emit an empty/misleading artifact. Tests use fixtures representing arbitrary hosts, never this repo's tree.

## Scope

Full M: (1) the deterministic map generator, (2) a standalone drift CLI, (3) the orchestrator `source-map` stage that records drift in run state and surfaces it. `source_files:` entries are **glob patterns** (not just exact paths). Drift surfacing is **read-only** — it never mutates authored pages; it reports into the dated What's-New entry and the notifier digest.

## Architecture — dual-view artifact (Approach 1)

Globs mean a pre-resolved exact-path inverse map alone cannot drive drift: a PR that _adds_ a file matching a page's glob is not a key in a map resolved before that file existed. So the generator materializes **two views** of the same `source_files:` data, and drift matches against patterns:

- **`map`** — the concrete inverse map `{source_path: [pages]}`, produced by resolving each page's globs against the repo's tracked files. This is the umbrella spec's shape and what C consumes for `file:line` citations.
- **`patterns`** — the raw `{page: [globs]}`, used by drift so added/renamed files matching a glob are still caught.

Both views derive deterministically from the same frontmatter; one regeneration per run.

Rejected: **resolved-map, lookup-only drift** (misses newly-added files matching a glob — exactly the case globs were chosen for; the orchestrator processes merged-PR metadata, so adds may not be on disk to resolve). **Patterns-only** (never materializes the concrete map the umbrella spec and C require).

## Output artifact

`<docs_dir>/.doc-source-map.json`, regenerated each run, auto-generated banner, overwritten:

```json
{
  "version": 1,
  "_generated": "auto-generated by engineering-docs-agent; do not edit",
  "map": { "scripts/auth/session.py": ["architecture/auth.md"] },
  "patterns": { "architecture/auth.md": ["scripts/auth/**/*.py"] }
}
```

## Design units

### 1. Map generator — `scripts/source_map.py` (new)

D/`contracts_doc`-shaped CLI: `--repo-root`, `--config` (required). Reads `site.docs_dir` from validated config; walks `*.md` pages under it; parses each page's frontmatter for `source_files:` (list of glob strings). Resolves every glob against the repo's tracked files (`git ls-files`; fallback below) via `_glob_to_regex`. Writes `<docs_dir>/.doc-source-map.json` (the dual-view artifact). Returns a JSON ledger to stdout: `{"written": [...], "pages_scanned": N, "mapped_sources": M, "skipped": [...]}`. Skips writing the artifact when no page declares `source_files:` (clean skip, `written: []`). Malformed frontmatter / non-list `source_files` → that page is recorded in `skipped` with a reason, never aborts. `ConfigError`/`yaml.YAMLError` → exit 1 with a one-line `error:` to stderr, no traceback.

### 2. Drift detector — `scripts/source_drift.py` (new)

CLI: `--repo-root`, `--config`; the changed-file list arrives on **stdin as a JSON array** of repo-relative paths. Collects each page's `source_files:` patterns via the shared helper (unit 5) — so drift does **not** require the artifact to exist and is independently testable. Matches every changed file against every page's patterns (`_glob_to_regex`); a match marks that page drifted. Emits `{"drifted": [{"page": "...", "changed_sources": [...]}], "changed_files_seen": N}`. Empty/invalid stdin → `{"drifted": [], "changed_files_seen": 0}`, exit 0.

### 3. Glob translator — `_glob_to_regex(glob) -> re.Pattern` (shared)

Explicit, stdlib-only translation (Python 3.9 `fnmatch`/`PurePath.match` mishandle `**`): `**/` = zero-or-more path segments, `**` = any (incl. `/`), `*` = a run of non-`/`, `?` = one non-`/`, every other regex metacharacter escaped, anchored full-match. Heavily unit-tested. Defined in `source_map.py`; `source_drift.py` imports it (no third module).

### 4. Orchestrator `source-map` stage — `scripts/orchestrator_runner.py`

Slots after the `archive-indexes` stage. Calls the generator (writes the artifact), then runs drift over the **union of the batch's PR `files[].path`**, records drifted pages in run state (a new `source_drift` field), and surfaces them as a **"Pages to review (source drift)"** block in the dated What's-New entry (which rides in the docs PR) and in the notifier digest — beside the existing "Gaps flagged" block. **Best-effort**: a generator/drift failure logs and continues; drift is advisory and must never block the docs-PR. Read-only — never mutates pages.

### 5. Shared page-pattern helper — `_collect_page_patterns(docs_dir) -> {page: [globs]}`

Single source for reading `*.md` frontmatter `source_files:` across `docs_dir`. Defined in `source_map.py` and imported by `source_drift.py`. Reuses the existing frontmatter-parse pattern (`archive_indexes.parse_frontmatter`); a malformed/missing block yields no patterns for that page.

### 6. Deliberate boundaries (YAGNI)

- **No subagent contract/schema.** M's CLIs are _deterministic_ (like `archive_indexes`/`contracts_doc`), called directly — not LLM-dispatched. No `scripts/contracts.py` dataclass and no `agents/schemas/*.json` (those validate subagent outputs). The drift result is internal run-state, surfaced in What's-New/digest.
- **No new config schema.** `source_files:` is page frontmatter, not config. The stage runs whenever `docs_dir` exists and skips clean otherwise. No `templates/config.schema.json` change.

## Data flow

```
config.site.docs_dir ─┐
site-src/*.md (source_files: globs) ─┤
                       ├─► source_map.py ──► .doc-source-map.json  (map + patterns)
git ls-files ──────────┘                         │  (C uses `map` for file:line citations)
                                                  │
PR files[].path (source-collector) ──► source_drift.py ──► drifted pages
                                                  └─► run state ─► What's-New block + digest
```

## Degradation & error handling

- **No `source_files:` anywhere** → empty map → generator skips writing; drift is a no-op.
- **Not a git repo** → `git ls-files` unavailable → filtered `rglob` from repo-root (excluding `.git`, `.venv`, `node_modules`, `site`, `__pycache__`). If neither yields files, `map` is empty but `patterns` are still recorded so drift works on the change set.
- **Glob matches nothing** (documents a not-yet-existing path) → absent from `map`, retained in `patterns`.
- **Malformed frontmatter / non-list `source_files`** → page skipped + recorded; never aborts.
- Both CLIs exit 1 with a clean one-line `error:` (no traceback) on config/YAML errors; the orchestrator stage is best-effort and never halts the pipeline.

## Testing strategy

TDD, fixture-driven (arbitrary-host fixtures; `python3 -m pytest`):

- **Glob translator** — `**/`, `**`, `*`, `?`, literal escaping, full-anchor, no-match.
- **Generator** — pages with globs → expected `map` + `patterns`; empty-case skip-clean; non-git `rglob` fallback; malformed-frontmatter skip; artifact overwritten each run.
- **Drift** — modified existing file drifts its page; **newly-added file matching a glob drifts** (the Approach-1 justification); renamed/deleted file; unrelated change = no-op; empty stdin = no-op.
- **CLIs** — subprocess: JSON ledger/output shape, `--config`, stdin contract, clean error exit.
- **Orchestrator stage** — monkeypatched dry-run: stage records drift in run state and emits the "Pages to review" What's-New block; absent-convention host → stage is a clean no-op; generator/drift exception → logged, pipeline continues.

## Sequencing / branch

## Decisions locked

- **A.** Dual-view artifact (`map` + `patterns`) — Approach 1; concrete map for C, patterns for glob-correct drift.
- **B.** `source_files:` are **glob patterns**, matched via an explicit stdlib `_glob_to_regex` (no third-party glob lib).
- **C.** Drift is **read-only** — surfaced in the What's-New entry + notifier digest; never stamps page frontmatter.
- **D.** Deterministic CLIs — no subagent contract/schema, no config-schema change.

## Risks & open questions

- **Glob semantics precision.** `**` handling is the main correctness risk; pinned by the dedicated translator unit tests. Case-sensitivity follows the host filesystem for resolution but the regex match is case-sensitive on POSIX paths.
- **Merge reconciliation with D.** The shared What's-New / orchestrator-stage surface means a small conflict with D is likely at merge; mechanical, not architectural.
- **Renames in drift.** A pure rename shows as delete+add in `files[]`; the added path matches via patterns, so the page is flagged — acceptable. Line-level (vs file-level) drift is out of scope (umbrella spec is file-level).
