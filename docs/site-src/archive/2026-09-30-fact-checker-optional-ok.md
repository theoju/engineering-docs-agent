# Decision: the fact-checker schema no longer requires `ok`

**Date:** 2026-09-30. **Ticket:** CCE-197. **PR:** #306.

## Decision

`agents/schemas/fact_checker.schema.json` now requires only `verdict`. The `ok` field is still declared as a boolean, so an agent that emits it is not rejected, but omitting it is valid.

The canonical schema block in `agents/fact-checker.md` and the typed view in `scripts/contracts.py` changed in the same PR. `tests/agents/test_schema_md_sync.py` asserts the schema file and the fenced block stay `json.loads`-equal.

## Why

The orchestrator's fact-checker consumer reads `verdict` and `findings` only. It never reads `ok`.

On nightly run 36741357748 (2026-09-30), one fact-checker dispatch returned a complete answer: a `contradiction` verdict and one fully populated finding. It omitted `ok`. The schema listed `ok` as required, so the answer was discarded and recorded as `fact_checker_unavailable`. The run then went blind, and auto-merge was skipped as `blind_run`.

## Measured breakdown

The run made 16 fact-checker dispatches:

- 16 parsed as JSON.
- 15 carried `ok`.
- 1 omitted `ok`.

Of the 15 that carried `ok`, 12 were `consistent` and 3 were `contradiction`. So 3 of the 4 contradictions did include `ok`.

The omission is model variance, not a rule tied to contradiction verdicts. That is why the fix is tolerance in the schema rather than a prompt change alone.

The verbatim payload is kept as `tests/fixtures/cce197/20260930T161538-fact-checker-no-ok.stdout.txt`, with context in `tests/fixtures/cce197/README.md`. `tests/orchestrator/test_fact_checker.py` validates it and asserts that `ok` is declared but not required.

## The class: a schema stricter than its consumer

This is the same failure shape as CCE-180 and CCE-125. A schema demands a field its consumer never reads, and a usable answer becomes a handled failure.

CCE-125 handled the gap-detector's `needs_spec: null` the same way. There the consumer did handle the value, so the schema was widened to match.

When you write or change an agent schema, check each `required` entry against what the consumer actually reads. Require only those.

## Consequences

- A fact-checker answer without `ok` is accepted. `verdict` is still required, so an answer missing it, or carrying an unknown verdict, still fails schema.
- Fact-checker dispatch failures remain advisory and info-only. This change removes one spurious trigger of them.
- The published contract page for the fact-checker is generated by `scripts/contracts_doc.py`. Regenerate it; do not hand-edit it.
