Throwaway prototype · CCE-160

Which fix survives every shape the JS suite can print?

A gate in the test suite runs a JavaScript test suite in a separate program, reads the summary it prints, and decides whether to let the build through. It has to catch a suite that quietly ran nothing — because a suite that runs nothing still reports success. Right now it reads that summary with a pattern that breaks the moment the output arrives in colour, which is what happens in every agent session.

Four candidate fixes are on the table. This page runs all four side by side against every situation the gate can meet, so we can see which one is right everywhere rather than argue about which one sounds safest.

The situation right now

The JavaScript suite itself
Healthy = 53 real tests pass. Hollow = the suite exists but runs nothing. Broken = real failures.
Colour forced on by the environment
Off in a normal terminal and in CI. On in every agent session — that is the whole bug.
A future release renames the summary
The default report is written for humans, so its wording is not a promise. Simulates it printing “passed” instead of “pass”.
The machine-readable report is available
Two of the four fixes ask for it by name. If a future release drops it, they have nothing to read.

What each candidate fix decides

Candidate fix Verdict Is that the right answer?
Correct the gate agreed with reality.
False alarm a healthy suite was rejected — safe, but it costs someone an afternoon.
Let it through a suite that ran nothing, or failed, was waved past. This is the one that must never happen.
