# CCE-105: API Reference Grouping and JSON-Schema Contracts Extractor

**Date:** 2026-06-09
**PR:** [#119](https://github.com/theoju/engineering-docs-agent/pull/119)
**Ticket:** CCE-105 (Phase 2a — docs-site remediation roadmap)

## Decision

Group the previously flat API reference into logical sections using a new optional `site.sections[].groups` schema field. Activate the dormant JSON-schema contracts extractor to surface agent output contracts as first-class documentation pages.

## Context

The API reference had grown to 22 modules with no grouping. A flat list at that size is not scannable. Engineers looking for orchestrator internals had to scroll past lint, setup, and integration modules to find them.

The JSON-schema extractor in `gen_ref_pages.py` was already wired but never activated. The agent output contracts in `agents/schemas/` had no published representation in the docs site.

## What Changed

**`gen_ref_pages.py`** gained an `assign_group(ident, groups)` function that implements first-match-wins assignment. It accepts both dotted (`scripts.orchestrator_runner`) and path-form (`scripts/orchestrator_runner.py`) identifiers. Hosts without declared groups see unchanged flat layout — the function degrades cleanly.

**`site.sections[].groups`** is a new optional schema field. Six logical groups cover all 22 modules:

| Group | Scope |
|---|---|
| Orchestrator | Core runner and state management |
| Generators | Content authoring and page generation |
| Lint | Tiered linting rules and runner |
| Setup | Discovery, scaffolding, and host detection |
| Verification | Publish verification and fidelity gates |
| Integrations | Jira, Slack, GitHub integrations |

No module falls through to an unclassified fallback. The group structure is correct at the SUMMARY level.

**JSON-schema contracts extractor** is now active against `agents/schemas/`. It generates 7 contract pages plus an index, making every subagent's output contract addressable by URL.

**`preflight_host._proposed_site`** gained two generic discovery hooks — `contract_sources` and `api_groups` — so the setup skill automatically proposes the extractor and groups on conforming hosts. Hosts that lack `agents/schemas/` are unaffected.

## What Is Not Yet Visible

The group structure is correct in the SUMMARY file but does not yet appear in the site nav. Nav visibility requires CCE-106 to wire literate-nav to consume the reference SUMMARY. The design spec for CCE-106 (`docs/superpowers/specs/2026-06-08-cce106-section-overviews-home-design.md`) was committed in this PR as a forward-looking artifact; a separate archive entry should be created when CCE-106 lands.

Do not treat the absence of nav grouping as a regression — the pre-CCE-105 state was also flat in the nav. CCE-106 is Phase 2b.

## Design Constraints Honored

**Generic-first.** The `assign_group` function and the discovery hooks only activate when the host config declares groups. A host repo with no `sections[].groups` gets the identical flat layout it had before, with no errors.

**No doc targets in `api/reference/`**. Those pages are auto-generated by mkdocstrings. The doc targets for CCE-105 are `architecture/api-reference-grouping.md` (architecture explanation) and this archive entry (decision record).
